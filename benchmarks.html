Deep Dive

The abstention problem: 70.0%

30 questions in LongMemEval are "false premise" — they ask about information that was never mentioned. A correct system should recognize it doesn't know and abstain. Graphonomous gets 9 of 30 wrong, confidently returning irrelevant results.

Root Cause

Heuristic-only detection

Abstention uses a simple confidence gap check: gap < 0.05 OR mean_score < 0.25 OR results < 3. After cross-encoder reranking inflates scores, even irrelevant results look confident — the gap threshold never fires. 9 of 30 false-premise questions pass with high-looking scores.

Comparison

SOTA achieves 100%

agentmemory correctly identifies all 30/30 unanswerable questions using a six-signal retrieval weighting system with learned confidence calibration. The gap between 70% and 100% represents the difference between heuristic rules and learned thresholds.

Contributing Factor

RRF score dilution

When multi-query fusion normalizes scores across rankers, semantically weak matches get artificially inflated. For abstention questions (where nothing should match), this means noise looks like signal.

Contributing Factor

No negative evidence modeling

The system has no concept of "this information doesn't exist in the graph." It always returns the top-K most similar results, even when the best match is poor. Abstention requires reasoning about absence, not presence.

Gap Analysis

What the numbers reveal

Critical

Abstention: 70.0% (30 questions)

9 false-premise questions answered confidently. Heuristic threshold-based detection fails after cross-encoder reranking inflates scores. Need learned calibration or an explicit abstention classifier.

Critical

Preferences: 67.7% (30 questions)

Entity extraction misses preferences entirely ("I prefer Thai food" has no capitalized entities). BM25 is useless for preference queries because answer keywords don't overlap with question keywords. Needs fact-augmented indexing.

Moderate

Temporal: 85.1% (127 questions)

No temporal metadata used in ranking. Turn indices and session timestamps exist but aren't indexed or queried. No temporal intent detection ("first", "latest", "before X"). Dual timestamp support (document vs event date) is missing.

Moderate

No LLM judge (measurement gap)

QA proxy score (session hit + keyword recall + session recall + evidence recall + NDCG) approximates but doesn't equal real QA accuracy. Competitors use GPT-4o judge on generated answers. True accuracy is likely 84–85%.

Strength

Knowledge Update: 97.1%

Belief revision and superseded edges work. When facts change across sessions, Graphonomous correctly retrieves the latest version. 100% session hit rate on update questions.

Strength

Latency: 1.5s mean

From 20s+ down to 1.5s mean across 500 queries. Cross-encoder reranking dominates at ~1.3s; all other stages under 150ms. Competitive with systems that call frontier LLM APIs per query.

Roadmap

Path to 95%

Five phases targeting the gaps above. Estimated impact based on published ablation studies and SOTA system architectures.

Phase 1 — Measurement

Add LLM judge + answer generation to benchmark. Current QA proxy is a useful directional metric but not comparable to competitor evaluations. Feed (question, retrieved_context) to Claude, judge answer quality 0/0.5/1. Establish honest baseline.

Impact: measurement accuracy, no direct score change

Phase 2 — Abstention + Preferences (+8–12pp)

Replace heuristic abstention with learned threshold calibration. Add fact-augmented key expansion for preference indexing (extract "prefers Thai food" as indexed facts, not raw text). Expand entity extraction to capture preferences, acronyms, and non-capitalized concepts.

Expected: abstention 70% → 95%+, preferences 68% → 85%+

Phase 3 — Temporal Intelligence (+3–5pp)

Dual timestamps (documentDate vs eventDate). Temporal intent detection ("first", "latest", "before X"). Time-aware query filtering. Turn-level and session ordering in retrieval ranking. Published ablations show +7–11% on temporal questions alone.

Expected: temporal 85% → 92%+

Phase 4 — Multi-Session Enhancement (+2–3pp)

Relax session diversity penalty for multi-session questions. Chain-of-retrieval with multiple rounds. Cross-session entity aggregation. Session-level NDCG-based scoring refinement.

Expected: multi-session 87% → 92%+

Phase 5 — Query Intelligence (+2–3pp)

Query expansion and reformulation (standard RAG technique, rephrasing queries 3 ways). Adaptive retrieval depth based on query complexity. These are the techniques that push from good to SOTA.

Expected: overall 88% → 95%+
System Configuration

How the benchmark was run

Embedder

nomic-embed-text-v2-moe (768D) via ONNX. Dense-forward export running all experts with router-weighted blending. Task-prefixed queries ("search_query:") and documents ("search_document:").

Retrieval Pipeline

Hybrid ANN (HNSW) + BM25 with reciprocal rank fusion. Cross-encoder reranking (ms-marco-MiniLM-L-6-v2). Graph neighborhood expansion (1–2 hops). Adaptive limits scaling with sqrt(node_count).

Graph Scale

940 sessions ingested (10,866 turns). ~12K knowledge nodes, ~208K edges. Session-level + turn-level + entity linking edges. Full topology analysis per query.

Evaluation

Self-contained QA proxy: 35% session hit + 25% keyword recall + 20% session recall + 10% evidence recall + 10% NDCG. No external LLM judge. Abstention scored binary on confidence gap heuristic.

Hardware

Single-machine Elixir/OTP runtime. EXLA for neural embeddings. SQLite + ETS for storage. No GPU required for inference (CPU-only ONNX). Total evaluation: 13 minutes for 500 queries.

Dataset

LongMemEval oracle split (ICLR 2025). 500 questions across 7 types testing 5 memory abilities. ~115K tokens per question context. Each question has 1–6 evidence snippets with session-level ground truth.
